1. **Box‑Cox / Yeo‑Johnson transforms** (λ optimised automatically) of the most skewed continuous columns:

2. **Polynomial extensions of the strongest physics‑driven predictor** `axial_load_per_cross_section = axial_load_kn / cross_section_cm2`:  
   - `ratio_sq` = (`axial_load_per_cross_section`)²  
   - `ratio_cubed` = (`axial_load_per_cross_section`)³  
   - `log_ratio` = log(`axial_load_per_cross_section` + 1)

3. **Three‑way interaction** that couples load, vibration and temperature:  
   `load_vib_temp` = `axial_load_per_cross_section` × `vibration_rms_mm_s` × `ambient_temperature_c`.

4. **Quadratic terms for geometry**:  
   - `slenderness_sq` = (`member_length_m` / √`cross_section_cm2`)²  
   - `length_log` = log(`member_length_m` + 1)

5. **Smoothed frequency encodings** for the three original categorical columns (`operator_shift`, `site_region`, `sensor_vendor`): count of occurrences per category divided by total rows, with Laplace smoothing.

**Justification:**  
The latest Evaluator rounds show a modest RMSE (~0.31) despite extensive pairwise load‑centric interactions and target‑mean encodings, indicating that the model still lacks sufficient non‑linear capacity to capture residual structure. Box‑Cox/Yeo‑Johnson transforms reduce skewness, enabling linear models to exploit hidden variance. Higher‑order powers and a three‑way load‑vibration‑temperature interaction target known physics (stress‑strain coupling under thermal effects) that are not captured by simple pairwise terms. Quadratic geometry features and frequency encodings add fresh information without removing any existing columns, satisfying the additive requirement and giving the Coder a clear implementation path. This exploratory expansion should provide new signal for the Evaluator to improve predictive performance.
